# 页面宠物素材制作规范与分镜

日期：2026-09-06。关联：[实现方案](./pet-mvp-implementation-plan.md)。

状态：前期制作说明。尚未生成或定稿角色图、逐帧动画；下列尺寸和预算为小样起点。

## 1. 视觉方向

网站已有纸白半透明卡片、海蓝文字、青绿交互和少量金色。建议小狗采用暖白/浅米毛色、深海蓝眼鼻、轻微手绘线条、柔和体积，不用荧光色、发光底座、大面积投影或写实复杂毛发。小领巾可用现有 sky/teal 配色，角色轮廓不能依靠领巾才能辨认。

默认三分之二侧面朝左，像在看页面。头部略大、眼鼻清楚，身体保持狗的比例。PC 80px、移动 60px 显示时都需可读；禁止仅以放大画面好看作为验收标准。

先锁定一张基准 idle、一张侧视结构参考、一张表情参考，再做同角色变形与动画。生成式概念图可以用来确定外形，但不能把九次独立生成图直接当成可连续播放的九动作。

## 2. 角色和导出约束

- 建议每帧 192×192px RGBA，透明背景；脚底锚点建议 (96,164)。所有动作共享画布、角色基准比例和锚点。
- 四边保留运动余量；兴奋动作不可裁掉耳朵，尾巴不能越界。透明余量参与命中框与视觉大小评估，不能只交一个大空白画布。
- 母版保留分层可编辑源文件：身体、头、眼睛、耳朵、尾巴、前后腿、配饰、轻微接地阴影。阴影作为独立层，不烘焙白底。
- 每帧轮廓粗细一致，脚接地时不能因重绘缩放产生抖动。不在每帧加入文字、气泡或水印。
- 生成源图后用本地脚本清背景、隔离主体、裁切并对齐，输出连续编号无损透明 WebP 母帧，再打包静态 WebP 图集；图集不是 animated WebP。所有动作另有 WebP 首帧静态导出，可降级。最终交付和网页请求的图片统一为 WebP。
- 单图建议最多 8 列 × 6 行，即 1536×1152，约 6.75MiB RGBA 解码内存。超出拆页，不无限横向堆帧。
- 帧间是否加 padding、图集行列数由统一导出脚本固定；manifest 必须记录，渲染不得猜测。

## 3. 九动作分镜表

以下帧数均为建议母帧输出量，可复制稳定帧形成停顿；最终以实际观感决定，不强求连续每帧重画。

| 动作 | 分镜 | 建议帧数 / fps | 播放规则 |
| --- | --- | --- | --- |
| idle | 稳定站立、轻微呼吸、一次眨眼、尾尖小摆 | 24 / 12 | 温和循环；减少动画取静态帧 |
| sit | 站立→后腿收起→坐稳→短停→站回 | 24 / 12 | 单次；首尾回统一姿势 |
| happy | 抬头→摇尾两次→轻微眯眼→回位 | 18 / 12 | 点击/拖后单次，幅度小 |
| curious | 耳朵稍立→歪头→停顿→回正 | 24 / 12 | 适合时间线/地点 |
| excited | 身体蓄力→前掌小抬或微跳→稳落→摇尾 | 18 / 12 | 不整体飞出画布，不闪光 |
| sniff | 头部低下→鼻尖两次轻探→抬头 | 24 / 12 | 作品/圣地，不画夸张气味线 |
| look | 眼睛先转→头转向左上→停顿→回正 | 24 / 12 | photo.open，默认看向内容 |
| drag | 身体轻收、四爪微垂、耳尾小摆 | 12 / 12 | 可循环，表现轻盈；不用痛苦表情 |
| sleep | 坐伏→闭眼呼吸→睁眼起身 | 36 / 12 | 单次小睡；不无限占用调度 |

随机 blink/tail_wag 可由 idle 内微动作体现，yawn 本期不强制单独素材；sit/look/sleep 可直接复用。首版完整交付九种有辨识度动作，不能用整体 translate/rotate 冒充闻、坐、睡等骨骼动作。

拖动可从任意帧中断。为了不出现切换闪跳，drag 与其他动作保持角色中心和大致头部位置；允许短暂姿势切换，不用复杂混合动画。动作结束回统一 idle 首帧。look 若需朝另一侧仅翻转角色，不翻转文字/菜单；带不对称花纹时先评估镜像是否合适。

## 4. Manifest 契约草案

```ts
interface PetAnimationAsset {
  id: 'idle' | 'sit' | 'happy' | 'curious' | 'excited'
    | 'sniff' | 'look' | 'drag' | 'sleep'
  src: string
  staticSrc: string
  frameWidth: number
  frameHeight: number
  columns: number
  rows: number
  frameCount: number
  fps: number
  padding: number
  anchor: { x: number; y: number }
  loop: boolean
}
```

文件名示例：idle.sheet.webp、idle.static.webp、drag.sheet.webp。路径由 Vite import 管理内容哈希，不新增 Worker 静态资源接口。完成时间由 frameCount/fps 推导，不另写一份不一致的 duration。多页图集需扩展 pages 字段后统一渲染，本期优先控制每动作单张。

## 5. 制作顺序与检查

1. 基准角色：暖白小狗方向，输出大图与 80px/60px 对照；检查深色背景、纸白卡片和首页照片上的可辨识度。
2. 先做 idle / drag / happy 三动作小样，验证中断、点击、透明边缘、缩放和内存。小样不合格先修母版，不批量生产。
3. 按九动作表补齐其余六动作，检查统一轮廓、光线、脚底锚点和配饰连续性。
4. 工程打包为透明静态 WebP 图集，校验尺寸、帧数、总量、首尾、缺帧、清晰度。所有动画都有静态 fallback。
5. 浏览器按实际 60px/80px 播放和快速切换，弱网与减少动画情况下验证。资源预算以实现方案目标为准，超标优先减少重复帧、分批加载或降低画布，而非直接模糊压缩角色。

验收不接受：不透明背景、脚底漂移、尾巴被裁、角色品种/毛色跨动作变化、深浅边缘白色光晕、移动端看不清表情、只有 PNG 姿势却宣称完成逐帧动画。

## 6. 概念图制作描述（供下一阶段使用）

> 为一个中日双语音乐 fan site 设计原创陪伴小狗角色 **Jean**。
>
> Jean 是一只**浅奶油色 / 浅金色的金毛寻回犬（Cream Golden Retriever / Light Golden Retriever）**，整体毛色以暖白、奶油米色和非常浅的金色为主。保留金毛犬典型特征：自然下垂的柔软耳朵、温和的脸部轮廓、稍宽但不过分厚重的口鼻、自然蓬松的尾巴和友善沉静的神态。
>
> 角色气质温柔、安静、亲近人，同时带一点对周围事物的好奇感。
>
> Jean 拥有**深海蓝色的眼睛和鼻子**，颈部佩戴一条**小型青蓝色领巾**，作为角色最主要的视觉识别元素。
>
> 采用适合网站 Mascot 的轻量化角色设计：
>
> - 三分之二侧面，身体与脸部整体朝左
> - 全身完整显示
> - 四肢轮廓清晰
> - 金毛犬特征明确，但进行适度卡通化与简化
> - 轻微手绘感轮廓
> - 柔和、干净的色块上色
> - 不描绘复杂的单根毛发
> - 仅通过少量柔和边缘与色块变化表现胸前、耳朵和尾巴的蓬松感
> - 避免写实摄影感
> - 避免过度幼犬化、Q 版化或大头比例
> - 保持自然、轻巧、温柔的身体比例
>
> 特别针对网页小尺寸显示进行设计：当角色缩小至约 **60px 高**时，仍然能够清楚辨识：
>
> - 金毛犬自然下垂的耳朵
> - 深海蓝色鼻尖
> - 深海蓝色眼睛
> - 青蓝色领巾
> - 前后四肢
> - 尾巴
> - 身体朝向
>
> 轮廓需要简洁、具有明确 silhouette，不依赖细小纹理表现角色特征。
>
> 站姿为自然放松的标准站姿，四肢着地，身体稳定，头部略微抬起，以轻微好奇但安静的神情望向左前方。尾巴自然放松并带有轻微弧度，不做夸张动作。
>
> 统一柔和光线，低对比阴影，整体色调温暖、安静、干净，与偏蓝色系的音乐 fan site UI 能够自然融合。
>
> 这是 **Jean 的角色母版 / Character Master Reference**。后续所有坐下、开心、好奇、闻嗅、观察、兴奋、拖拽、睡觉等动作，都必须严格基于该母版：
>
> - 相同品种
> - 相同脸型
> - 相同身体比例
> - 相同毛色
> - 相同眼睛颜色
> - 相同鼻子颜色
> - 相同领巾颜色与造型
> - 相同绘画风格
>
> 不得因动作变化而改变角色设计。
>
> **无背景、透明背景、无场景、无地面装饰、无文字、无 Jean 名字文字、无 logo、无水印、无额外配饰。**

以上为早期领巾版描述，当前衣服版制作以第 7 节为准。不能依赖一张多格概念图自动获得工程上可用的透明动画帧。

## 7. 当前衣服版与素材处理流程

- 角色为 Jean，沿用奶油色金毛及深蓝色眼睛、鼻尖。以 `assets/pet/jean-shirt-concept-v1.png` 为参考，穿浅黄色无袖衣服，青蓝色包边，衣服上体现 Jean 名字及蜜蜂图案，不再佩戴领巾。
- 生成阶段优先要求均匀纯色底，不绘制棋盘格。透明度由本地脚本处理，不依赖生成器直接输出透明 WebP。
- 脚本依次完成背景清除、当前帧主体隔离、裁切、统一锚点和画布对齐，再输出透明 WebP。浅色毛发与背景接近时仍需人工检查边缘，不能把所有浅色像素直接删除。
- 多格源图的格宽和角色边界未必准确。裁切向邻格扩展时必须排除邻格碎片；同样的输出尺寸不能保证帧内内容正确。当前动作小样保留最大连通主体，未来若有独立特效，应单独分层处理，避免误删。
- 最终交付和页面请求的图片统一为 WebP；无损 WebP 保存源图和透明母帧，页面使用压缩后的透明 WebP 图集。
- 打包后检查帧尺寸、透明边界、邻帧污染、图集与母帧对应关系、首尾循环，并在浅色和深色页面背景中检查播放及拖拽效果。
