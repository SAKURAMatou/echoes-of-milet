# 巡礼与站内照片存储兼容

照片类型 `B` 使用 blog R2 桶，`M` 和 `S` 使用 milet R2 桶。公开端与管理端继续通过现有同源 `/static/blog/img/`、`/static/milet/img/` 代理访问，无需新增 API、代理白名单或数据库迁移。

## 修复范围

- Worker 巡礼相册与封面查询保留 `img_type`；封面和缩略图使用预览图，大图和下载使用原图。缺少预览图或预览文件名等于原图时回退到原图。
- 巡礼 KV 缓存改用 `v2` 键，部署后绕过旧的七天缓存。管理端已有的全部、城市、区域和地点缓存失效操作继续生效；旧键随 TTL 自然过期。
- 地点没有相册、相册为空或旧数据未提供照片数组时，详情保留地点说明与导航，显示中日文无照片提示。合集不生成空封面图片请求。
- 旧格式图库照片、相册封面及演出视觉图根据 `storage`、图片类型或访问路径识别桶。独立图片预览页同时支持两个桶。
- 图库、图片搜索、文章和通用图片组件的下载入口统一设置下载参数，保留已有查询参数和锚点，避免重复拼接。下载仍使用原图。
- Worker 图库列表兼容相册封面为 null，避免一个空封面导致整页相册被吞掉；共享图片路径工具兼容不完整数据。
- 图库列表使用 `GALLERY:v2` 缓存前缀，绕过历史缓存的空列表；已有管理端的 `GALLERY` 前缀清理同时覆盖新旧键。
- 管理端专辑封面、卡片图片、文章插图/封面及演出/场馆选图保留桶路径；旧图片选择器兼容仅提供预览相对路径的响应。

## 验证

公开端：`npm run type-check`、`npm run build:ssr`、`node --test tests/pilgrimage/spot-photos.test.mjs`，以及原有路线动画测试。使用 `npm run verify:ssr:local:watch` 的生产数据检查桌面与移动端的无相册地点。

管理端：`npm run type-check`、`npm run build`。

Worker：`npx vitest -c vitest.unit.config.mts run`。本次照片相关测试通过；全量结果为 183 通过、7 失败。已有失败涉及缺少 `0028_article_preview_revision.sql`（5 项）、timeline 输入校验（1 项）和 `PilgrimageConflict` 的组件依赖边界（1 项），不属于照片改动。

本地 SSR 验证服务读取生产 Worker 数据，代码改动不会自动更新生产响应。需要同步部署 Worker 和公开端才能在生产看到巡礼 blog 照片地址修复；管理端修复也需部署管理端。
